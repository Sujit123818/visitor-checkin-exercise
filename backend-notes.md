# Backend Track Notes

## Completed Fixes

### 1. Deactivated visitors appeared in the active visitor list

The visitor index endpoint originally filtered only on `checked_out_at: nil`. A visitor who had been deactivated but had not been checked out was therefore still returned as active.

The fix adds `active: true` to the visitor index query. This ensures deactivated visitors are excluded from the active list while preserving the existing response structure.

### 2. Visitor list performed N+1 host queries

The visitor serializer returns `host_name` through the `visitor.host` association. Before the fix, the index action loaded each host lazily while serializing the response.

The fix adds `includes(:host)` to the index query. Hosts are now eager-loaded before serialization, avoiding one host query per visitor.

### 3. Deactivated visitors appeared in repeat-visit search

The repeat-visit search originally matched visitors by name without checking the `active` flag. Deactivated visitors could therefore be returned as suggestions and selected for repeat visits.

The fix scopes the search query to `active: true`. Active matching visitors remain available, while deactivated visitors are excluded without changing the response structure.

Each of the three fixes has a request spec in `api/test/controllers/api/visitors_controller_test.rb`. The specs cover active-list filtering, eager-loaded host queries, and exclusion of deactivated search results.

## Performance Measurement

### Methodology

I measured the SQL queries generated by `GET /api/visitors` using an `sql.active_record` notification subscriber in the request test. The test creates two active visitors with hosts, performs the request, and counts the visitor and host `SELECT` queries.

### Results

| Version | Queries for visitor list | Result |
|---|---:|---|
| Before the fix | 3 for 2 visitors | 1 visitor query plus 2 host queries, demonstrating N+1 behavior |
| After the fix | 2 for 2 visitors | 1 visitor query plus 1 eager-loaded host query |

The existing development log also showed the same pattern at page size 20: one visitor query plus 20 host queries, for 21 Active Record queries in total. After adding eager loading, the request uses two queries regardless of the number of visitors on the page.

## Deliberately Unfixed Defects

The incomplete visitor-record defect remains unfixed. The `Visitor` model currently has no presence validations, so the API accepts missing registration fields. Fixing it would preserve the current JSON response shape for successful requests but would introduce `422 Unprocessable Entity` validation responses for invalid requests. It was not selected because the three completed fixes more directly address the specified active-visitor workflow and the identified performance issue.

The timezone/display defect was subsequently fixed by configuring Rails with `Asia/Kathmandu` and formatting timestamps in the receptionist's browser-local timezone in the frontend.
